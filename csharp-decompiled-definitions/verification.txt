C# decompiled assembly definitions — issue #1440

Environment: Windows desktop, native Tauri application, csharp-ls 0.28.0,
Unity 2022.3.62f3 and a .NET 8 C# fixture. Both fixture paths contain spaces.
Screenshots and recording were captured with this change on main 7d267ab5,
before rebasing the unchanged feature onto main 915fec59 (commit bfb6ff18).

Before: StringBuilder hover resolves but Go to Definition returns no locations.
See before.json and before-1-plain.png.

After, native application:
- StringBuilder / Append open read-only C# documents from System.Runtime.
- MonoBehaviour / CancelInvoke open a read-only UnityEngine.CoreModule document
  at the positions returned by csharp-ls, with the assembly name in the banner.
- The actual navigate.declaration action opens MonoBehaviour, follows Behaviour,
  returns to project source and opens CancelInvoke; navigation-flow.mp4 records it.
- Repeated navigation reuses the document; back/forward retains the source position.
- Editing is rejected, saving does not modify project files or assemblies.
- Missing metadata reports an error and leaves the current editor usable.
- Decompiled views have no project pull diagnostics (Unity's language version would
  otherwise report errors in csharp-ls's decompiled modern C#).
See after-plain.json, after-unity.json and recording.json for actual assertions.

Protocol/editor regression coverage:
- Opt-in is scoped to csharp-ls. Other servers retain their existing responses.
- Raw spaces and Unicode in csharp: URIs are encoded before typed deserialization;
  existing escaping and opaque data/command arguments are preserved.
- Source-generated documents keep their source label and pull diagnostics.
- Metadata errors can be retried and virtual-document caching is reused.
